# Remote burst settling

Sources: [missed second remote during half duplex](https://github.com/laberning/home_io_control/issues/209), [unheard KLR200 movement](https://github.com/laberning/home_io_control/issues/207). Their shortened logs support scheduling scenarios (class C), not complete RF captures. Tests are synthetic (class S).

Local console: `iohc remote settle GROUP HEX_CHANNEL_MASK QUIET_MS`. Groups 1..4 are volatile and default disabled. Bit 0 selects channel 1. Example `iohc remote settle 1 0003 2000` explicitly groups channels 1 and 2 with two seconds of quiet. At least two paired 2W actuator channels are required; quiet time is 500..30000 ms. Mask zero disables a group. A known mapped 1W remote must already link to a member. Unknown remotes, malformed actions and replies cannot trigger it.

A heard action defers group follow-up until quiet. Every member receives one scheduling request, including a member whose own remote was missed. The existing channel epoch/backoff, 10-minute tracking, queue, scan/command priority, duty admission and low-power spacing remain responsible for actual status reads. Active epochs coalesce; this is not a second poll engine or a movement replay. A group cannot dispatch more than once per minute; continuous/noisy bursts expire after ten minutes. Busy/scan states defer dispatch. Member key/node/revision, gateway or system-key changes invalidate the configuration. Storage is allocated only when enabled.

No heard remote means no event catch-up. Use the existing ETS periodic poll (`ParamIOHC_cPollInterval`) for eventual correction of unseen foreign movement. Its loop runs outside active tracking; low-power intervals are clamped to 60 seconds. Use infrequent battery-device intervals (for example an hour), or disable it. No extra periodic timer, automatic OPEN or broad network poll is introduced. Confirm on hardware that both group members update under the original half-duplex scenario; native scheduling tests cannot prove RF reception.
